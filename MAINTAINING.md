# Maintaining the provider

How to build, test, regenerate and release this provider. Everything here is read from the repo and its workflows; anything unconfirmed is listed under [Open questions](#open-questions). `CONTRIBUTING.md` has the detail on CI, auto-merge and the live acceptance suite.

## Where code comes from

The provider is generated by the [Speakeasy CLI](https://www.speakeasy.com/docs/speakeasy-reference/cli/getting-started) from an OpenAPI spec plus overlays, all under `.speakeasy/`:

| File | Role |
|---|---|
| `in.openapi.yaml` | OpenRouter API spec. Updated by spec PRs (`sdk-bot/openapi-update-*`) from the monorepo release flow |
| `private-endpoints-overlay.yaml`, `speakeasy-modifications-overlay.yaml`, `terraform-entities-overlay.yaml` | Overlays applied on top of the spec (the last one maps operations to Terraform resources and data sources) |
| `out.openapi.yaml` | Spec after overlays. Generated, do not edit |
| `workflow.yaml` | Source, overlay and target definition. Pins `speakeasyVersion` |
| `gen.yaml` | Generator options, including `persistentEdits` and `versioningStrategy: automatic` |
| `gen.lock`, `workflow.lock` | Generator state. `gen.lock` holds `releaseVersion`, which drives releases |
| `patches/` | Patch files |

Change behavior by editing the spec, overlays or `gen.yaml`, not the generated Go under `internal/`. Direct edits to generated files are kept only as Speakeasy [custom code](https://www.speakeasy.com/docs/customize/code/code-regions/overview) (`persistentEdits`), and only if the change is made through the CLI's workflow.

## Build and test

Needs the Go version in `go.mod` and, for the stub acceptance tests, a Terraform CLI.

```sh
go build ./...
go test ./... -timeout 15m                              # offline: unit + httptest-backed stub tests
TF_ACC=1 OPENROUTER_MANAGEMENT_KEY=sk-or-mgmt-... \
  go test ./internal/acceptance/... -v -parallel 4 -timeout 30m   # live, test org only
```

The live suite must only run against a dedicated $0-credit org. See "Running the Acceptance Tests" in `CONTRIBUTING.md`. The offline PR gate (`.github/workflows/ci.yaml`) also runs `go mod tidy -diff`, gofmt, `go vet` (both skip `internal/sdk`), `actionlint`, `terraform fmt -check examples` and `goreleaser check`; run the same locally before pushing.

## Regenerate

Normally you do not run generation by hand: open a PR that changes a file under `.speakeasy/` and `.github/workflows/regenerate.yaml` regenerates the provider and pushes a `chore: regenerate provider (vX.Y.Z)` commit to your branch (same-repo branches only). Pull before pushing again.

To regenerate locally, for example to inspect a diff or debug a failure:

```sh
speakeasy run --target open-router --skip-testing --skip-upload-spec --auto-yes --output console
go generate ./...        # renders docs/ with tfplugindocs; needs a Terraform CLI
```

`workflow.yaml` pins `speakeasyVersion`; the CLI switches to that version itself. `regenerate.yaml` adds `--skip-versioning` when the branch is already ahead of `main`, otherwise the run bumps `releaseVersion`. Locally, add `--skip-versioning` unless you want a bump. The workflows pass `SPEAKEASY_API_KEY`; whether a local run needs one (the source in `workflow.yaml` has a registry location) is untested here.

Agent skills for this work are in `.agents/skills/` (see its `README.md`). `speakeasy agent context` prints current CLI documentation.

## Release

A release is `releaseVersion` in `.speakeasy/gen.lock` changing on `main`:

1. A PR that changes Speakeasy inputs is regenerated by `regenerate.yaml`. That commit carries the `gen.lock` version bump. If another PR released first, merge `main` into the branch and the next run bumps again.
2. Merging to `main` with `.speakeasy/gen.lock` changed triggers `.github/workflows/sdk_publish.yaml` (also runnable with `workflow_dispatch`).
3. `acceptance-gate` runs the full live acceptance suite against the test org. A failure blocks the release; fix the cause and re-run the workflow.
4. `release` reads `releaseVersion`, skips everything if a GitHub release `v<version>` already exists (so re-runs are safe), otherwise tags `v<version>` on `main`, imports the GPG key and runs GoReleaser (`.goreleaser.yml`). It publishes signed zips, `SHA256SUMS` and `terraform-registry-manifest.json` to the GitHub release. Nothing in the workflows notifies the Terraform Registry (see open questions).
5. `RELEASES.md` is the Speakeasy-generated release log. Do not edit it by hand.

Spec updates from the monorepo and fallback regeneration PRs merge themselves through the `openrouter-docs-sync` app (see `CONTRIBUTING.md`), so most releases need no manual step. To release something by hand, land a change that regenerates, or run the `Generate` workflow (`sdk_generation.yaml`, `workflow_dispatch`, optional `set_version`) to open a regen PR, then merge it.

If a release is cut wrongly, do not delete tags or releases without checking with the owners: the Terraform Registry caches published versions.

## Secrets and apps the workflows need

`SPEAKEASY_API_KEY`, `GH_DOCS_SYNC_APP_ID` / `GH_DOCS_SYNC_APP_PRIVATE_KEY` (the `openrouter-docs-sync` app; must be a ruleset bypass actor on `main`), `TERRAFORM_GPG_SECRET_KEY` / `TERRAFORM_GPG_PASSPHRASE`, and `OPENROUTER_MANAGEMENT_KEY` in the `acceptance-testing` environment. A maintainer with repository admin has to manage these.
